# Atlas Agent Engine managed memory for Python

This additive feature is a separate slice in the [implementation map](../implementation-map.md).
[ADR 0019](../../decisions/0019-separate-atlas-agent-engine-managed-memory.md) records the rationale;
the feature follows the repository's normal review and release process.

## Boundary

Add a separate Python `ContextProvider` in `agent_framework_mongodb.atlas_agent_engine_memory`.
Keep the [direct MongoDB Memory provider](memory.md), its public API and document model, and all
.NET packages unchanged. The new adapter uses the public `agent-engine-sdk-memory` package, not
the LangGraph or Google ADK runner. The SDK dependency MUST be opt-in and MUST NOT raise the
minimum Python version for the base package.

The adapter records conversation turns and retrieves context from a user-configured hosted Atlas
Agent Engine project. It does not implement a fact extractor, create its own storage schema,
provide exact chat history, or manage Atlas provisioning, indexes, or lifecycle. Atlas can
extract durable memories from recorded turns according to the project's configuration. The
adapter MUST disclose that behavior and default to recall without recording.

## Required behavior

- Accept a caller-owned `Memory` client and an explicit, trusted user identifier. Never derive
  authorization scope from messages, model output, or model-controlled options. The adapter MUST
  require a nonempty session identifier when recording or requesting short-term conversation
  recall. It MUST NOT close the injected client or any bound handle sharing that transport.
- Retrieve private memory with a user constraint enforced by the SDK/service. Long-term recall
  can span sessions for the same user; short-term recall MUST be constrained to the current
  session. Inject only nonempty attributed context, framed as data rather than instructions.
- When enabled, record only eligible text from newly completed runs, excluding replayed history,
  provider-generated context, and tool calls and results. Require a stable, scoped idempotency
  key that survives a retry of the same logical write. An SDK acknowledgement means accepted for
  recording, not extracted or searchable durable memory.
- Support composition with direct MongoDB Memory using distinct source IDs. Neither provider may
  ingest context generated by the other. Document that enabling both writers intentionally
  persists conversation data in two systems.
- Keep synchronous SDK operations off the Agent Framework event loop. Propagate cancellation,
  report documented operational failures through the existing adapter-boundary resilience and
  redaction conventions, and do not claim that cancelling an await rolls back a remote write.
- Support only the hosted project-scoped SDK transport in the initial slice. Do not silently
  fall back to app-bound transport, unscoped reads, or a different retrieval mode.

## Required validation

| Validation | Required evidence |
| --- | --- |
| Public framework hooks and SDK boundary | Scoped and attributed recall, explicit opt-in recording, exclusion of replay and generated context, stable retry keys, cancellation and redaction |
| Compatibility | Existing direct Memory tests, wheel and sdist smoke tests without the SDK, and opt-in install and runtime tests on the declared Python and SDK versions |
| Hosted service | Synthetic turns in a dedicated project, user and session isolation, recording and recall, deduplication, and cleanup restricted to test data |

Hosted checks MUST skip cleanly without credentials. A skip is not hosted validation.
